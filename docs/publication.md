# Проверка публикации

После клонирования выполните `npm run hooks:install`. Установка действует только
для текущего репозитория, делает хуки исполняемыми и настраивает `core.hooksPath`.
Если уже настроены другие хуки, установщик остановится: проверки нужно объединить,
сохранив существующие действия.

- `npm run check:publication` проверяет текущие отслеживаемые и неигнорируемые файлы.
- `npm run check:staged` проверяет **весь Git-индекс**, читая содержимое объектов Git.
  Исправление или удаление файла только в рабочей папке не изменяет подготовленный коммит.
- `node scripts/checkPublication.mjs --ref=HEAD` проверяет дерево выбранного коммита.
- `pre-commit` запускает проверку индекса; `pre-push` проверяет конечные деревья
  отправляемых ссылок и каждый исходящий коммит, включая промежуточные изменения.
  Для новой удалённой ветки проверяется вся доступная история. Неполная история
  и недоступные объекты останавливают проверку; сначала получите историю через fetch.

Игнорируются локальные настройки, сертификаты, ключи, данные, сборки, кеши,
временные файлы и рабочие планы. Принудительное добавление таких файлов также
блокируется проверкой. Исходники, миграции, публичная документация и шаблоны
настроек остаются в репозитории. Диагностика сообщает путь, строку и категорию,
не печатая содержимое строк. Имя файла выводится, даже если находка относится к нему.

Workflow `Publication policy` повторяет проверку истории в GitHub без установки
зависимостей. Для блокировки слияния его можно включить в обязательные проверки
защищённой ветки. CI запускается после загрузки объектов в GitHub, поэтому
основная защита до отправки — локальные хуки. Их можно отключить средствами Git;
новые клоны требуют установки хуков.

Правила обнаруживают запрещённые файлы и известные признаки приватных данных,
но не распознают любой возможный пароль или токен в произвольном тексте.
Проверка не очищает уже опубликованную удалённую историю. Публичные изменения
нужно просматривать перед коммитом; обнаруженные ранее опубликованные секреты
требуют замены и отдельного согласованного исправления истории.

Клиент и сервер публикуются независимо, поэтому каждый репозиторий содержит
собственную автономную копию проверяющих скриптов. Изменения общей политики
нужно переносить в обе копии и проверять их тестами.
