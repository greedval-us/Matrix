# Обновление клиента

Клиент проверяет последнюю опубликованную версию через три секунды после запуска,
затем каждые 30 минут. Проверка использует сервер, API-ключ и встроенный CA из
обычного подключения. Отдельный адрес обновлений настраивать не нужно.

Если на сервере есть более новая версия для текущей платформы и архитектуры,
справа в верхней панели появляется значок скачивания с точкой. Он открывает
номер версии, описание изменений и действия:

- «Загрузить обновление» скачивает файл с отображением прогресса. Загрузку можно отменить.
- «Обновить и перезапустить» доступна после проверки файла в Windows portable.
  Завершите текущую работу перед нажатием: активные поиски остановятся при выходе.
- Для установленного клиента и Linux доступна кнопка «Скачать файл». В portable
  эта кнопка появляется только как запасной вариант при ошибке подготовки замены.

Ручная проверка доступна в разделе настроек. Проверка не запускает скачивание и
не перезапускает приложение. Старый сервер без поддержки обновлений и сервер без
опубликованной версии не показывают значок.

## Portable Windows

Приложение скачивает новую сборку во временный каталог своего профиля, проверяет
размер и SHA-256, затем по явному нажатию готовит замену. Помощник Windows проверяет
свою готовность до закрытия приложения, ждёт завершения Electron и portable-оболочки,
заменяет исходный EXE и запускает его снова. Имя и расположение EXE сохраняются,
профиль пользователя остаётся прежним. Права администратора не запрашиваются.

Во время замены помощник создаёт резервную копию. После подтверждения запуска
нового клиента он удаляет старый EXE. При сбое запуска он пытается восстановить
прежнюю версию. Если запуск не удалось подтвердить, копия сохраняется.
Диагностика находится в каталоге профиля приложения `updates/install-<id>/install.log`.
Копии `.matrix-backup-<id>.exe`, созданные прежним обновлятором, можно удалить
вручную после проверки новой версии.

Новые сборки и файл, сохраняемый через «Скачать файл», называются `model 404.exe`
для Windows. Автообновление сохраняет имя и путь уже используемого EXE.

Для установленной Windows-версии предоставляется скачивание portable EXE, без
изменения установленного приложения. На Linux скачивается AppImage с правом
выполнения; замена и запуск выполняются вручную. Поддерживаются Windows
x64/arm64/ia32 и Linux x64/arm64 при наличии соответствующей серверной сборки.

## Публикация новой версии

1. Увеличьте `version` в `package.json` и согласуйте `package-lock.json`.
   Используется стабильный номер `major.minor.patch`, например `1.0.28`.
2. Соберите приложение с доверенным CA:

   ```bash
   npm run build:portable -- /path/to/server-ca.crt
   ```

3. Передайте готовый EXE администратору сервера. В репозитории `matrix-server`
   выполните публикацию, указав версию, совпадающую с версией внутри сборки:

   ```bash
   npm run release:publish -- --file "/path/to/model 404.exe" --version 1.0.30 --platform win32 --arch x64 --kind portable --directory /path/to/releases --notes "Описание изменений"
   ```

Сервер сам рассчитывает размер и SHA-256, сохраняет неизменяемый файл и атомарно
публикует описание. Разные байты нельзя публиковать под тем же номером версии.
Серверу нужен модуль `releases` и доступ для чтения к `MATRIX_RELEASES_DIR`.
Подробности Docker и хранения описаны в `matrix-server/docs/client-releases.md`.

Первую сборку с этим механизмом нужно распространить обычным способом: прежние
версии клиента ещё не умеют проверять обновления. Включение обновлений не означает
автоматическую публикацию, загрузку на рабочий сервер или смену его сертификата.

## Проверки разработки

`npm test` проверяет протокол, размер/хеш, отмену, восстановление после ошибок,
IPC, интерфейс и portable-помощник. Windows-тесты помощника используют безвредные
временные EXE и не изменяют запущенный клиент. `npm run build:client` и
`npm run test:preload` проверяют сборку и изолированный мост.

После сборки `electron scripts/checkVisuals.mjs --updates-only` проверяет окно
обновления на тестовых данных, включая светлую/тёмную темы и минимальный размер
окна; настоящий сервер и установщик при этом не вызываются.
